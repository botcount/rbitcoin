Fixed

- **A scripthash index fault no longer wedges the chain.** A `Corrupt` or I/O error from the SH index during a disconnect, from a write-behind append, or from a history, listunspent or count read of a torn key used to fail the block or every read of that key (`scripthash extent last page not ver=2`) and leave the node unable to disconnect or connect, with `RBITCOIN_SH_FORCE_REBUILD` unreachable below tip. The index is now marked degraded: blocks keep connecting and disconnecting with SH deferred, Electrum and Esplora address routes answer `scripthash index rebuilding` (503), and a background supervisor waits for in-flight reads, wipes the index, rebuilds it from Class A, and re-arms write-behind. A read that overlaps the fault, the rebuild, or a disconnect's unlink batch is refused with a 503 instead of returning a partial answer. A `store/scripthash.degraded` marker, published with a synced rename and directory fsync, makes a restart wipe the broken index at open; it is removed only after the replacement head's `SEAL` and `include_hwm` are durable. `RBITCOIN_SH_FORCE_REBUILD` now also wipes at open, not only at tip entry. `RBITCOIN_SH_AUTO_REBUILD=0` (a new flag, default on) leaves the index degraded until a restart. A write-behind error that is not a scripthash `Corrupt` or I/O error still halts as before. No schema change. The wipe also clears the ingest and sealed overflow heads, which a cold rebuild used to leave in place.
